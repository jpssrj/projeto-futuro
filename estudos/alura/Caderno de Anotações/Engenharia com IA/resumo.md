# Engenharia de Software na era da IA
Neste primeiro curso, podemos entender o que é possível gerar com o auxilio da ia, nesse caso, o professor utilizou o claude code por exemplo para a criação do projeto do curso.

Entendemos que nossa profissão vem mudando com o tempo, deixamos de ser apenas desenvolvedores hard coded para profissionais que são experiêntes no uso da ia para agilizar e melhorar nosso ambiente de desenvolvimento e entrega de tasks. Entretanto, devemos entender que a inteligência artificial é muito boa, mas **não substitui o profissional**, a IA pode auxiliar o programador a entregar mais rápido, mas ainda hoje é visto que para tomar decisões de negócio e boas práticas, ela necessita de auxilio, muitas vezes entregando resultados como grandes "gambiarras" apenas para funcionar naquele momento.

Se o desenvolvedor não souber o que precisa fazer, qual tecnologia está utilizando ou a lógica por trás da feature implementada, ele será apenas um "fantoche" na mão de um robô.

## Boas práticas e planos de orquestração
Ao longo do curso, entendemos como usar planos gerados para criação das nossas aplicações, dessa forma, entregamos um documento auto explicativo para que o agente possa entender e utilizar todo o contexto necessário para criar uma aplicação mais profissional.
Diferente de apenas dizer "faça uma tela de login", um desenvolvedor de verdade e preocupado com o futuro do projeto deve indicar stacks, métodos utilizados, se serão utilizadas apis prontas, blibliotecas, frameworks e muitas outras grandes coisas que são importantíssimas para longo e médio prazo.
O Sloop Dev é exatamente esse profissional, que entrega prompts vagos, e recebe projetos vazios e com falhas.

## Você sabe o que é MCP?
É um servidor local que utilizará boas regras para integrar a um sistema e/ou entregar melhores resultados, o Figma MCP, por exemplo, serve para conectarmos o agente ao figma, fazendo com que ele possa seguir de forma mais fiel o projeto que temos estruturado de forma gráfica no app.
Outro exemplo de MCP é o GitHub MCP, onde conectamos uma chave ao agente e com isso, é possível a ia acessar o código fonte no github e criar PRs quando encontrar bugs ou então for adicionar novas features.

## SDD - Spec-Driven-Development o novo jeito de trabalhar
Com isso tudo, devemos entender que os programadores devem aprender a lidar e trabalhar com os agentes para assim extrair o máximo do poder deles, hoje em dia não adianta mais dizer que você apenas coda a mão, sem a utilização da ia você entregará tasks com um tempo mais longo, portanto, é impressindível que o desenvolvedor saiba orquestrar o agente para que assim, possa ter o máximo dele em suas mãos.

## CODE REVIEW - O que tomar cuidado
Se o agente gerou o código, o profissional deve ir e fazer um code review no mesmo, por isso a grande necessidade do desenvolvedor saber da stack que está utilizando, pois caso quebre, e tenha toda certeza, **vai quebrar**, o programador sabe onde pode estar errado e o que deve arrumar. Além disso, vale para um olhar crítico também, o dev precisa criticar o que está sendo gerado, métodos utilizados e como a lógica está sendo implementada no projeto, dar observações de melhorias e saber tratar erros são as coisas mais importantes que diferenciam um profissional VibeCoder de um desenvolvedor que usa a ia ao seu favor.
